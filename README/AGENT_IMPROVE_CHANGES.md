# Agent Improve 변경 사항

비교 기준: `origin/main`의 `33eac65` (`feat: resolve merchant timeouts through human support`)

이 문서는 위 Main 기준과 비교해 `agent-improve`에서 추가되거나 달라진 내용만 정리한다.

## 1. 고객 문의 이해와 Case 유형 보정

- 고객이 빠른 선택과 다른 문제를 후속 메시지로 설명하면 전체 대화와 주문 맥락을 다시 확인한다.
- 문의 유형을 `PROVISIONAL`, `CONFIRMED`, `LOCKED` 단계로 관리해 초기 분류를 후속 설명으로 보정할 수 있다.
- 유형 변경이 필요할 때 내부 분류명을 고객에게 노출하지 않고 자연스러운 확인 질문과 `네/아니요` 선택지를 사용한다.
- 이미 매장 요청이나 최종 조치가 진행된 Case는 유형을 임의로 변경하지 않고 새 문의를 안내한다.
- `치킨`, `찌개` 같은 일반 표현은 고정 메뉴에 연결하지 않고 현재 주문 메뉴 안에서 의미를 해석한다.
- 고객이 말한 메뉴가 주문 내역에 없으면 다른 메뉴로 임의 치환하지 않고 주문 메뉴를 제시해 다시 확인한다.
- 한국어 화면에서도 영어 문의를 감지해 영어로 답하고, 한국어와 영어 외의 언어에는 지원 언어를 안내한다.

## 2. 고객 정보 충분성 및 사진 판단

- 위험 신호가 없는 누락·오배달 Case는 매장에 묻기 전에 고객 설명이 충분한지 LLM이 판단한다.
- 설명이 부족하면 나머지 메뉴 수령 여부, 포장 상태, 당시 상황과 사진을 한 번에 요청한다.
- 같은 상세 질문을 반복하지 않고 고객 답변 후 매장 확인 단계로 이어간다.
- 고객 사진은 Vision 분석을 거쳐 `주장 뒷받침`, `판단 불충분`, `주장과 충돌`로 구조화한다.
- 사진 분석은 관찰 가능한 내용과 한계를 함께 저장하며 책임이나 고의성을 확정하지 않는다.

## 3. 주문과 메뉴 맥락을 유지하는 Agent Loop

- 현재 문의 유형에 해당하는 Tool 이력만 사용해 이전 유형의 판단 결과가 새 판단을 오염시키지 않게 했다.
- 고객이 메뉴를 정정하면 해당 메뉴의 금액과 주문 대비 비율을 다시 계산한다.
- 매장 확인 전 고객 설명 보충 여부를 LLM이 판단하고, 충분하면 기존 Agent Loop를 그대로 진행한다.
- 정책과 Risk 결과는 Main의 기준을 유지하며, 반복 환불 등 위험 신호가 있으면 매장 확인보다 상담원 검토를 우선한다.
- 매장 부인·발생 가능성·확인 불가 응답은 자동 이관하지 않고 고객이 문의 종료 또는 상담원 추가 확인을 선택하도록 대기한다.
- 상담원 이관이 완료된 고객 화면은 `상담원에게 이관되었습니다. 이제 상담원이 이어서 도와드릴게요.`를 마지막으로 표시하고 입력창과 추가 선택지를 닫는다.

## 4. 사장님 화면과 매장 대화

- 고객의 마지막 문장을 그대로 보여주지 않고 전체 대화와 주문 내용을 바탕으로 고객 주장을 LLM이 한 줄 요약한다.
- 고객 대화 원문은 별도 토글에서 확인할 수 있다.
- 빠른 답변은 다음 네 가지로 정리했다.
  - 문제 확인 및 환불·재배달 동의
  - 정상 포장·전달 주장
  - 문제 발생 가능성
  - 확인 어려움
- 빠른 답변은 확인 버튼을 한 번 거쳐야 Agent에게 전달되므로 잘못 누른 답변을 바로 수정할 수 있다.
- 별도의 `에이전트에게 답변 제출` 단계 없이 선택 확인이나 자유 입력 즉시 Agent가 후속 대화를 진행한다.
- 매장 자유 입력은 LLM이 주문, 고객 주장, 사진 분석과 기존 대화를 함께 보고 구조화한다.
- 매장이 고객 사진이나 추가 설명이 필요하다고 자유 입력할 수 있으며, Agent가 현재 Case에 실제로 필요한지 판단한 경우에만 고객에게 요청한다.
- `사진 확인 후 조건부 조치`는 고객 사진이 첨부된 Case에서만 표시한다.
- `2,000원 쿠폰 지급`은 누락 메뉴가 5,000원 이하이면서 주문 금액의 30% 이하인 경우에만 표시하고 실행 시에도 조건을 다시 검증한다.
- 상담원이 매장에 작성한 질문은 `상담원`, 자동 Agent 질문은 `상담 에이전트`로 구분한다.

## 5. 상담원 화면

- 고객 주장, 매장 응답, 이관 사유, 확인해야 할 사항을 실제 Case 데이터 기반의 LLM 요약으로 표시한다.
- 고객과 매장의 진술은 확인된 사실처럼 단정하지 않고 시스템·Tool 확인 사실과 구분한다.
- 기존 `Agent Summary`를 `확인해야 할 사항`으로 바꾸고 `주의할 점 → 확인해야 할 점 → 다음 조치` 순서로 구성한다.
- 반복 환불 제한은 내부 코드명 대신 상담원이 바로 이해할 수 있는 표현으로 표시한다.
- 이관 사유에는 필요한 조치 지시를 섞지 않고 자동 처리가 중단된 이유만 요약한다.
- 실제 고객·매장 대화는 요약과 구분된 작은 대화창 및 토글에서 확인한다.
- 고객 첨부 사진과 Agent의 사진 관찰 결과·한계·주의 문구를 함께 표시한다.
- AI 요약 생성에 실패하면 원문 기반 임시 요약과 재시도 버튼을 제공한다.
- 상담원 화면에서 `고객에게 추가 정보 요청` 선택지를 제거해, 이관 이후 고객 추가 확인은 상담원이 실제 상담 과정에서 직접 판단하도록 경계를 단순화했다.
- 상담원이 매장에 추가 질문한 Case는 기존 대화를 유지하고 답변 도착 후 상담원 대기열로 돌아온다.

## 6. Demo 데이터와 주문 표시

- 고객 화면에서 모든 Demo 주문을 선택할 수 있다.
- 고객 이름은 고정 문구가 아니라 선택한 주문의 고객 정보와 연동한다.
- Demo 주문 시각, 픽업 시각, 예상 도착 시각과 완료 시각은 실행 기준 시각에 맞춰 표시한다.
- 진행 중인 Demo 주문은 주문별 고정 지연값을 유지하고, 완료 주문은 현재 시각 때문에 다시 지연 상태로 바뀌지 않는다.
- 주문 상태는 한국어 화면에서 `배달 중`, `픽업 완료`, `배달 완료`로 표시한다.
- 배달 중에는 도착 예정 시각과 지연 분을, 완료 주문에는 배달 완료 시각을 표시한다.

## 7. Case와 사진 상태 유지

- Case 상태를 Local Storage에 저장하고 `BroadcastChannel`로 고객·사장님·상담원 탭 사이에 변경을 공유한다.
- 첨부 사진은 IndexedDB에 보관하고 Case에는 참조값을 저장해 화면 이동이나 새로고침 후에도 다시 불러온다.
- 고객, 매장, 상담원 간 왕복 과정에서 기존 대화와 Tool Trace를 유지한다.

## 8. OpenAI API 확장

- API 연결 상태와 사용 모델을 화면 하단의 작은 상태 배지로 확인할 수 있다.
- 다음 구조화 API가 추가 또는 확장됐다.
  - 고객 자연어 이해 및 문의 유형 재평가
  - 고객 정보 충분성 판단
  - 고객 사진 분석
  - 매장용 고객 주장 요약
  - 매장 자유 입력 해석 및 고객 추가 자료 필요성 판단
  - 상담원 인수인계 요약
- API가 연결되지 않은 경우 기존 보수적 Rule fallback을 사용하며 확인되지 않은 사실을 생성하지 않는다.

## 9. 화면 문구와 Demo 표현

- 서비스명을 `배달 CS Agent 이음이`로 통일했다.
- Main의 역할 진입 영역을 고객·사장님·상담원 화면을 확인하는 Demo 안내로 정리했다.
- 사용자에게 노출되는 `Mock 환불`, `Mock 보상` 등의 표현을 환불, 재배달, 쿠폰으로 바꿨다.
- `mock_refund`, `mock_redelivery`, `mock_coupon` 같은 내부 enum은 기존 계약 호환을 위해 유지한다.
- 고객 화면 최초 안내, 주문 상태, 해결 안내와 사장님·상담원 문구를 한국어·영어 리소스에 맞춰 정리했다.
