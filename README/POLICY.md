# CS Policy v2

> 구현 기준: `고객 CS Agent 서비스 로직 v2`
> 최종 수정일: 2026-10-07 KST

이 문서는 `src/features/cs/policy.ts`와 `projectPolicy.ts`에 구현된 현재 규칙을 설명한다. 아래 숫자는 실제 플랫폼 내부 정책이 아닌 프로젝트 시뮬레이션 값이다.

## 프로젝트 시뮬레이션 값

| 설정 | 값 |
| --- | ---: |
| 자동 처리 메뉴 금액 상한 | 5,000원 |
| 자동 처리 주문 대비 비율 상한 | 30% |
| 최근 30일 유사 신고 상한 | 2회 |
| 지연 보상 기준 | 30분 |
| Mock 지연 쿠폰 | 3,000원 |
| 매장 지연 알림 | 2분 |
| 매장 응답 타임아웃 | 3분 |
| 매장 추가 질문 | 최대 1회 |

설정값은 `PROJECT_SIMULATION_POLICY` 한 곳에서 관리한다.

## Route 원칙

```text
Fact + Evidence + Policy + Risk
→ 명확하고 저위험: 자동 처리 후보
→ 불명확: Merchant 확인
→ 충돌 또는 고위험: Human CS
```

LLM은 고객의 의도와 메뉴 표현을 이해하는 데 사용한다. 환불·재배달·쿠폰 허용 여부와 Route는 로컬 Policy와 Risk가 최종 결정한다.

## 고객 선택과 Action

- 해결 방법이 둘 이상이면 고객이 직접 환불 또는 재배달을 선택한다.
- Case는 선택 전 `ACTION_READY`, 실행 중 `ACTION_EXECUTING`을 사용한다.
- 환불과 재배달 Tool은 `caseId`, `orderId`, 메뉴를 조합한 멱등성 키로 중복 실행을 막는다.
- 사진 분석은 보조 Evidence이며 책임 주체를 확정하지 않는다.

## 배달 지연

| 실측 지연 | 허용 처리 |
| --- | --- |
| 0분 이하 | 정상 진행과 상태 안내 |
| 1~29분 | 실제 지연 시간·상태 안내, 배송 알림 제안 |
| 30분 이상 | 안내, 중복 보상 확인, 고객 동의 후 주문당 1회 쿠폰 |
| 데이터 없음 | 위치 추측 금지, 추가 확인 또는 Human CS |

실측 지연은 배달 중이면 현재 시각, 배달 완료면 실제 도착 시각을 예상 도착 시각과 비교한다.

## 메뉴 누락

먼저 주장 메뉴가 주문에 존재하는지 확인한다. 주문에 없으면 환불과 재배달을 모두 막고 다른 주문 선택을 안내한다.

다음 조건을 모두 만족하면 자동 처리 후보다.

```text
메뉴 금액 <= 5,000원
AND 메뉴 금액 / 주문 금액 <= 30%
AND 최근 30일 유사 신고 <= 2회
AND 동일 주문·메뉴 환불 없음
AND 환불·재배달 차단 Risk 없음
```

자동 기준을 초과하지만 위험 충돌이 없는 Case는 Merchant 확인으로 보낸다. Merchant가 문제를 확인하고 해결 조치에 동의하면 다시 Policy와 Risk를 평가한 뒤 고객에게 환불·재배달 선택지를 제공한다.

## 오배달

- 사진이 없으면 `WAITING_EVIDENCE`로 고객 증빙을 요청한다.
- 명확한 보조 증빙과 낮은 Risk가 있으면 자동 해결 후보가 될 수 있다.
- 증빙이 불명확하거나 같은 매장 내 포장 오류 가능성이 있으면 Merchant 확인으로 보낸다.
- Merchant가 해결 조치를 승인하지 않으면 고객에게 매장 답변을 전달하고, 고객이 문의 종료 또는 Human CS 연결을 직접 선택한다.

## Merchant 표준 응답

| 응답 | 의미 | 다음 처리 |
| --- | --- | --- |
| `CONFIRMED` | 문제 발생 인정 및 해결 동의 | Policy·Risk 재검증 후 고객이 환불·재배달 선택 |
| `POSSIBLE` | 문제 발생 가능, 해결 미승인 | 매장 답변 전달 후 고객이 종료·Human CS 선택 |
| `DENIED` | 정상 처리 주장, 해결 미승인 | 매장 답변 전달 후 고객이 종료·Human CS 선택 |
| `UNKNOWN` | 판단 불가 | 추가 자료 요청이 있으면 고객에게 전달, 아니면 고객이 종료·Human CS 선택 |

기존 저장 데이터의 `ADMITTED_MISSING`, `POSSIBLE_MISSING`, `CLAIMS_PACKED`, `PACKED`는 Case 복원 시 새 값으로 변환한다.

매장 요청 2분 후 지연 알림을 표시하고 3분 동안 응답이 없으면 전체 맥락과 함께 Human CS로 이관한다. 늦은 응답은 이미 완료된 Action을 다시 실행하지 않는다.

매장이 자유 입력으로 사진·영수증·포장지 등 추가 자료를 요청하면 Case를 `WAITING_EVIDENCE`로 전환한다. 요청 문구는 고객 채팅에 전달되며, 고객이 첨부한 자료는 같은 Case의 Merchant 대화로 다시 전달한다. 고객은 자료 제공 대신 Human CS 연결을 직접 선택할 수 있다.

## Risk

| Flag | 조건 | 자동 Action 제한 |
| --- | --- | --- |
| `duplicate_refund` | 같은 주문·메뉴의 완료 환불 존재 | 환불 차단 |
| `frequent_refund` | 최근 30일 유사 처리 2회 초과 | 환불·재배달 차단 |
| `order_claim_mismatch` | 주문에 없는 메뉴 주장 | 환불·재배달 차단 |
| `evidence_mismatch` | 증빙과 주장 충돌 | 환불·재배달 차단 |
| `high_value_claim` | 금액 또는 주문 대비 비율 초과 | Merchant Route 신호 |

## 귀책 추정

Case는 `CUSTOMER`, `MERCHANT`, `DELIVERY`, `PLATFORM`, `UNKNOWN` 중 하나를 기록한다. 귀책이 확정되지 않아도 고객 해결은 진행할 수 있지만 비용 책임이나 제재는 별도 검토한다.

## Human CS 전달

Human CS는 환불·재배달 승인 주체가 아니다. 고객이 직접 연결을 요청하거나 매장 무응답·배송 과정 분쟁이 발생했을 때 추가 정보 확인과 중재를 담당한다. 이관 시 주문·배달 사실, 고객 원문, 증빙 분석, Merchant 응답, 귀책 추정, Risk, Policy, 실행 Tool, 완료 Action과 이관 이유를 `agentSummary`에 저장한다.

## 복합 문의 데이터 모델

`CsCase.tasks`와 `activeTaskId`에 문의 Task와 상태를 저장한다. 현재 화면에서 생성되는 단일 문의도 Task 한 건으로 저장되어 이후 FIFO 복합 문의 실행기로 확장할 수 있다.
